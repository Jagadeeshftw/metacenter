| **This iteration** | Accrual-only. It can't be drawn automatically: `transfer-from-reserve` is private and uncalled, and using the reserve goes through a SIP process (<Pox5 lines="2692-2694" />). Automatic responses are anticipated for PoX-6. |

## How it grows

The reserve receives 15% of what remains after bonds (<Pox5 lines="2190" />). When no STX is staked it receives the whole remainder. In a shortfall there is no remainder, so it stays **flat**.

## How it can be used

`transfer-from-reserve` (<Pox5 lines="2696" />) is private and uncalled, so there is no automatic path from the reserve to bonds in this iteration; using the reserve goes through a SIP process. pox-5's own comment says so: it "can only be called by the node as part of consensus (via the SIP process)" (<Pox5 lines="2692-2694" />). The SIP authors describe the reserve as accrual-only during PoX-5 and say "a complete reserve model will be designed and ratified as part of the PoX-6 work" ([forum post #42](https://forum.stacks.org/t/introducing-the-bitcoin-staking-sip-v1-draft/18862/42)); the [Stacks docs](https://docs.stacks.co/learn/bitcoin-staking/rewards-and-tranches#coverage-ratio) say automatic on-chain responses are anticipated for PoX-6.

## Definitions

- `hypothetical cover = reserve ÷ (2 × obligation per interval)`, in cycles (two intervals per cycle), truncated to two decimals.
- **State:** "not drawing" when the latest deposit is positive, "flat" when it is zero.
